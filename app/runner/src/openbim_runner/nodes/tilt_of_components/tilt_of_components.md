# Node Development Prompt (RCC4ALL) — tilt_of_components

This file is the persistent memory for the **tilt_of_components** node. Read it
before starting any session on this node.

## Node identity
- **Name (registry key):** `tilt_of_components`
- **Category:** `geometry`
- **Purpose:** Measure the tilt of IFC building components relative to the
  horizontal plane and flag components outside a configured comparison threshold.

## Decided architecture (locked with user)
1. **Manual element-category selector** setting: `2d` (walls & slabs) vs `1d`
   (columns & beams) — picks the algorithm.
2. **Slim structured checks per element** (patterned on `property_comparison`),
   NO human-only-message result and NO spreadsheet export.
3. **Keep the 4-option comparison enum** + limit fields, tolerance
   default `0.1°`.
4. **Basic path only for v1:** two-biggest-surfaces (2D) / farthest-centroids (1D).
   Openings/VOIDS handling **deferred** (still works for walls with windows because
   the hole is already subtracted from the wall's mesh).
5. **Emit helper geometry** into the geometry cache (surface mesh 2D / thin axis
   cylinder 1D).

## Tilt semantics (important)
The tilt value is the **smaller angle between the element's dominant surface/axis
and the horizontal plane**: vertical wall/column = `90°`, horizontal slab/beam =
`0°`. The tilt is computed as follows:
- 2D surface: mean of `acos(-normal_z)` over the surface's triangles (in degrees),
  complemented to `180 - x` when `> 90.1`, rounded to 2 dp.
- 1D: area-weighted surface centroids, farthest pair = axis; tilt =
  `|acos(dot(axis, NEG_Z)/|axis|) * 180/pi - 90|`, rounded 2 dp.

## Node specification
### Settings — `TiltOfComponentsSettings`
- `element_category: Literal["2d","1d"]` (default `2d`)
- `comparison_method: Literal["greater_than_lower","less_than_upper","inside_interval","outside_interval"]`
- `lower_limit: float = 0.0` (used by `greater_than_lower`)
- `upper_limit: float = 90.0` (used by `less_than_upper`)
- `interval_lower: float = 0.0` / `interval_upper: float = 90.0`
  (  one interval reused by both `inside_interval` / `outside_interval`, since only
  one method is active at a time)
- `horizontal_separation_angle: float = 5.0` (°; facet-merging for curved objects)
- `tolerance: float = 0.1` (°)

### Flag logic (tolerance applied; `passed = not flagged`)
- `greater_than_lower`: flag if `tilt > lower_limit + tol`
- `less_than_upper`: flag if `tilt < upper_limit - tol`
- `inside_interval`: flag if `tilt > interval_lower - tol and tilt < interval_upper + tol`
- `outside_interval`: flag if `tilt < interval_lower - tol or tilt > interval_upper + tol`

### Inputs
- `express_ids: list[str]` — REQUIRED list of qualified element references
  (`<slug>:expr:<id>`), typically bound to `ifc_element_filter`. Each reference
  resolves against the model named inside it. An unbound input fails
  validation; an empty bound list processes zero elements.

### Result (slim structured; harmonized envelope)
- The executor wraps every node result in an outer envelope `{ label, type,
  result }`; `label` (runtime name) and `type` (`"tilt_of_components"`) are
  supplied there and are NOT part of the node's `result` object.
- `summary_element_count`, `summary_passed_count` / `summary_failed_count`
  (element-level: elements with ≥1 flagged surface/axis vs. none) and
  `summary_check_count` (total number of checks across all elements; 2 per 2D
  element, 1 per 1D element).
- `passed_express_ids`, `failed_express_ids`: flat lists partitioning the
  measured elements.
- `TiltCheck` (harmonized check schema):
  - `key`: `"surface_0"` / `"surface_1"` (2D) or `"axis"` (1D)
  - `check_parameter`: `"angle"`
  - `expected_value: str` (human-readable **pass** expectation, i.e. the
    inverse of the flag condition, combined from the comparison method and
    limits; `"less than or equal to X"`, `"greater than or equal to X"`,
    `"outside A and B"`, `"inside A and B"`; trailing `.0` trimmed; uses the
    **raw** configured limits, not the tolerance-adjusted boundary),
  - `actual_value: str` (°, stringified), `unit: "deg"`, `missing: false`,
    `passed: bool`,
  - `expected_value_condition`, `expected_value_min`, `expected_value_max` are
    present but always `""` (left as empty defaults: the tilt node encodes the
    whole expectation in the combined `expected_value` string rather than the
    structured condition fields).
- **No `message` field.** Human-readable text is generated by the downstream
  `bcf_output` node (consistent with `property_comparison`'s pure-logic design);
  the raw comparison method is not emitted apart from the `expected_value`
  wording.
- `TiltsElement`: `express_ids: list[str]` (normally a single qualified
  reference), `class_name: str` (IFC class or `unknown`), `failed: bool`,
  `checks: list[TiltCheck]` (note: `element_category` and check-level
  `geometry_key` were dropped from the emitted output by decision).
- `TiltOfComponentsResult`: `summary_element_count`, `summary_passed_count`,
  `summary_failed_count`, `summary_check_count`, `passed_express_ids`,
  `failed_express_ids`, `elements`
- 2D ⇒ up to 2 checks (front/back surfaces); 1D ⇒ 1 check (axis).
- Result shape mirrors the harmonized check convention (`key` / `actual_value` /
  `expected_value` / `unit` / `missing` / `passed`).

## Behavior / edge cases
- A missing entity or an element without tessellated geometry produces an
  element with empty checks and `failed=False`; a missing entity uses
  `class_name="unknown"`.
- **Composite / decomposed elements:** when an element has no own `Body` mesh but
  is decomposed via `IfcRelAggregates` into parts (e.g. multi-layer wall →
  `IfcBuildingElementPart`), its tilt is measured as a whole by merging the Body
  meshes of all its parts, recursing through the aggregation (`_resolve_composed_mesh`
  + `_collect_descendant_meshes`). Own `Body` takes precedence when present (no
  decomposition read). Parts remain listed & measured independently (keep-both).
  Depth-first with a `seen` set guards shared parts and decomposition cycles.
  This is buildingSMART-valid: `IfcBuildingElementPart` explicitly documents
  composite/sandwich walls modelled as per-layer elements.
- Validation `ValueError`: interval methods with `interval_lower > interval_upper`;
  `greater_than_lower` with negative `lower_limit`; `less_than_upper` with negative
  `upper_limit`; negative `horizontal_separation_angle`.
- `_group_surfaces` uses a grouping test: near-horizontal normals
  (`|z| < 0.99` and same vertical angle `< 0.001`) group by 2D horizontal angle
  `< horizontal_separation_angle`; otherwise group by 3D angle `< 1°`.
- Helper geometry keys: `inter:tilt_surface_{reference}_{surface_index}` (2D),
  `inter:tilt_axis_{reference}` (1D), where `reference` is the full qualified
  element reference. These are valid shared-cache keys for geometry consumers.
